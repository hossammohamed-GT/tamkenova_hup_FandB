# Certificate studio — 2026.1

## Architecture

This replaces the old canvas certificate compositor and both old background files. There are **exactly two templates**: `TRAINING` and `VOLUNTEER`. Both include English and Arabic fixed wording in a single design; language is not an editable certificate field.

- `public/certificates/training-v1.png` and `volunteer-v1.png`: complete 3508 × 2481 fixed artworks. Titles, descriptions, official logo, decorative elements, labels, background and institutional signature are baked into the pixels. No fixed words are drawn by application code.
- `*-thumb.png`: 900px derivatives for template selection and recipient cards, not extra templates.
- `*-v1.svg`: design masters generated by the build-time script, not used by the runtime renderer.
- `scripts/build-certificate-artwork.mjs`: deterministic, offline artwork builder (`npm run certificates:artwork`). Uses the bundled, OFL-licensed fonts and `@resvg/resvg-js`.
- `src/core/certificates/certificate-template.ts`: version, types, exact field manifest, validation, text fitting and record conversion rules.
- `certificate-renderer.service.ts`: shared admin preview and recipient/admin export implementation. It draws one artwork image, then only the allowed values. PDF is an A4 landscape document containing the same high-resolution image used for PNG export. No external QR/font/image service is involved.

### Brand and signature

Colors are the existing Tamkeenova identity colors: navy `#004265`, gold `#be8a3f`, ivory `#fcfaf5`. `brand-mark.png` is the mark extracted from the existing official `public/images/logo.svg` (its embedded color image and alpha mask, cropped to the mark), not a newly invented logo. The angular frames echo its geometry.

The signature is a **fixed typographic institutional endorsement, “Tamkeenova / إدارة تمكينوفا”**, not a forged individual's handwritten signature. No approved personal signature asset was present. If an authorized personal signature is required, incorporate the supplied asset at artwork-build time and publish a new template version; do not add a runtime signature field.

## Editable positions

All coordinates below are in the logical **1800 × 1273** design space, measured from the upper-left. Preview and export scale the complete artboard together.

| Field | Template | X | Y | Width | Height | Font size / minimum | Max lines |
|---|---|---:|---:|---:|---:|---:|---:|
| Recipient | Both | 280 | 533 | 1330 | 100 | 58 / 29 | 2 |
| Program | Training only | 290 | 762 | 1310 | 108 | 38 / 24 | 2 |
| Hours | Both | 270 | 938 | 260 | 65 | 42 / 28 | 1 |
| Date | Both | 610 | 938 | 310 | 65 | 34 / 26 | 1 |
| QR | Both | 1394 | 929 | 172 | 172 | — | — |

Text is centered inside each rectangle. Arabic and Latin fonts are self-hosted and explicitly loaded before drawing. Text wraps at word boundaries and shrinks only within its stated range. If it cannot fit, generation fails visibly: names are never truncated, squeezed horizontally, or allowed to overlap other content. The renderer also clips to the field bounds defensively.

The date is a timezone-independent `YYYY-MM-DD`. Hours are whole numbers, 1–100,000. Recipient names are limited to 120 characters; program names to 180. Blank text, control characters and bidi override controls are rejected. Names containing ordinary Arabic/Latin text are supported.

## Workflow

1. Admin opens `/portal/admin/certificates` and selects a design.
2. Select the existing recipient account (delivery/ownership metadata, not an additional printed field).
3. Confirm the recipient name, program for training only, hours and date.
4. The live preview uses the actual renderer. Empty fields use clearly disclosed example values. Preview QR codes are not issued credentials.
5. Save validates and pre-renders before calling the API. The server independently validates all allowed values, saves the name snapshot, template version and a cryptographically random verification code.
6. Download the issued PDF from the admin table, or PDF/PNG from the recipient certificate page. Volunteers have a certificate link in their dashboard; `/portal/certificates` is available to all authenticated recipients. The JWT-protected API selects records for the authenticated user, not a client-supplied user ID.
7. QR codes are generated locally with a four-module quiet zone and point to `{frontend-origin}/verify?code=...`. Never use a preview deployment to distribute production certificates; download them on the production frontend origin.

The API does not accept headings, descriptions, signatures, partners, PDF uploads, arbitrary QR URLs, verification codes or template versions as editable content. The previous PDF-upload endpoint and UI are removed. Admin-only revoke/delete operations remain available. Verification shows the saved recipient/program values and reflects revocation.

## API contract

`POST /api/admin/certificates` (ADMIN / SUPER_ADMIN):

```json
{
  "user_id": "recipient-account-uuid",
  "certificate_type": "TRAINING",
  "recipient_name": "Layla Ahmed Hassan",
  "program_name": "Leadership & Professional Development",
  "training_hours": 32,
  "issued_at": "2026-09-21"
}
```

For `VOLUNTEER`, omit `program_name` or send `null`. A non-empty program is rejected.

`PATCH /api/admin/certificates/:id` accepts any subset of the same fields **except `user_id`**. It validates the merged record. When changing training to volunteer, send `program_name: null`. This preserves the verification code, account owner, and validity state. Revocation is a separate endpoint and cannot be undone through a content edit.

Responses retain the existing `{ success, message, certificate }` envelope; the frontend unwraps this explicitly. `title` is compatibility metadata derived on the server (program name or “Volunteer Recognition”), never an editable artwork heading.

## Deployment — database step required

Deploy the additive database change **before** deploying the API:

```sh
cd tamkeenova-api
npm ci
npm run db:certificates  # requires the normal configured DATABASE_URL
npm run build          # regenerates Prisma and compiles Nest
```

`prisma/rebuild-certificates.sql` adds nullable `recipient_name`, `program_name`, and `template_version` columns. It is transactional and safe to re-run. It intentionally does not delete historical records or invent data. Do not replace it with a destructive database reset.

Historical rows have a NULL version. Their old template renderer is gone; verification remains available, but downloads require an admin to review the name, program, hours/date and explicitly convert the record in the editor. Unsupported `OTHER` records are never silently rendered as training certificates. Revoked records remain revoked after conversion.

Deploy the API and frontend together because the editable-field API contract has changed. Keep the versioned artwork/font files available for the lifetime of issued records. Future design changes should introduce new versioned assets and corresponding manifest entries rather than overwriting an issued design.

```sh
cd tamkeenova-hub_anguler
npm ci
npm run build
npm start -- --host 0.0.0.0
```

Development browser requests use `/api`, proxied by `proxy.conf.json` to the local backend on port 3000. Production builds use `environment.prod.ts` and its configured API host. The Angular host allowlist permits the Arena preview host. Global Google font inlining is disabled for reproducible offline builds; certificate fonts are bundled regardless.

## Tests

```sh
# Frontend field contract / bounds / wrapping tests
cd tamkeenova-hub_anguler
npm run test:certificates

# Browser workflow with intercepted HTTP fixtures (no production writes)
npx playwright install chromium
npm start -- --host 0.0.0.0 --port 4200
npm run test:certificates:e2e
# Optional: CERTIFICATE_TEST_URL and CHROMIUM_PATH environment overrides.

# API validation, issue/update and verification tests (Nest 12 ESM)
cd ../tamkeenova-api
npm run test:certificates
```

The browser tests cover both template types, Arabic values, mobile layout, issue/update payloads, PDF and PNG exports, a pixel comparison proving that pixels outside the dynamic rectangles are unchanged, and decoding the exported QR to the correct verification URL. Unit tests cover unsupported templates, invalid values, historical records, field bounds, no-overlap geometry, wrapping, fixed-field injection rejection, name snapshots and revocation.

Database migration and live database-backed issuance must still be tested in the deployment environment. The development browser tests use explicit API fixtures, not a real database. Sample certificate files produced by tests are previews, not issued credentials.
